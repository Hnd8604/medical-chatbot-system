# HAPI FHIR Setup Notes

## What Was Built

This folder contains the infrastructure slice for the Medical Chatbot project:

- HAPI FHIR JPA Server.
- PostgreSQL used only as HAPI FHIR internal persistence.
- PostgreSQL host port configured as `localhost:5434` for GUI inspection tools.
- Synthetic FHIR transaction Bundle with fixed IDs (generated).
- Python scripts to generate the dataset, wait for HAPI, seed data, and check FHIR connectivity.

Backend and frontend connect to HAPI through the FHIR REST API, not through HAPI PostgreSQL tables.

## How To Run

From the repository root:

```powershell
docker compose -f infra/hapi-fhir/docker-compose.yml up -d
python infra/hapi-fhir/scripts/wait_for_hapi.py
python infra/hapi-fhir/scripts/seed_fhir_data.py
python infra/hapi-fhir/scripts/check_connection.py
```

The local FHIR base URL is:

```text
http://localhost:8080/fhir
```

Backend services running inside the same Docker Compose network should use:

```text
http://hapi-fhir:8080/fhir
```

For database inspection tools such as DBeaver or pgAdmin:

```text
Host: localhost
Port: 5434
Database: hapi
User: admin
Password: admin
```

Compatibility dev login for existing pgAdmin profiles:

```text
User: postgres
Password: postgres
```

Only use this for inspection/debugging. Chatbot application code must still use FHIR REST APIs.

## Data Seeded

The dataset is generated by `scripts/generate_fhir_seed.py` into
`seed/synthetic-fhir-transaction-bundle.json`, then posted by `seed_fhir_data.py`.
Resources use fixed IDs and transaction `PUT`, so re-seeding updates existing
resources instead of creating duplicates. To regenerate:

```powershell
python infra/hapi-fhir/scripts/generate_fhir_seed.py
```

**100 records of each type** (500 total), cross-linked and clinically coherent:

| Resource | Count | ID scheme |
|---|---|---|
| Patient | 100 | `BN2026-00001` … `BN2026-00100` |
| Encounter | 100 | `ENC-2026-00001` … `ENC-2026-00100` |
| Observation | 100 | `OBS-2026-00001` … `OBS-2026-00100` |
| Condition | 100 | `CON-2026-00001` … `CON-2026-00100` |
| MedicationRequest | 100 | `MED-2026-00001` … `MED-2026-00100` |

Each patient owns exactly one Encounter, Observation, Condition and
MedicationRequest (all referencing the patient). Patients cycle through 10 realistic
clinical profiles (`patient_index % 10`): hypertension, type 2 diabetes,
hyperlipidemia, asthma, acute URI (resolved), gastritis, hypothyroidism, iron
deficiency anemia, osteoarthritis, migraine. See `README.md` for the full
profile → condition/observation/medication table.

Conventions:

- Phone: `09` + zero-padded index, e.g. `BN2026-00001` → `0900000001`.
- Identifiers: `http://medical-chatbot.local/patient-id` (= FHIR id) plus MRN `MRN-2026-000NN`.
- Observation values are randomized within realistic ranges; `interpretation` and `referenceRange` are set accordingly.
- Practitioners are referenced by `display` only (HAPI enforces referential integrity; no Practitioner resources are seeded).
- `BN2026-00002` and `BN2026-00052` share the name **Tran Thi Mai** for ambiguous-patient selection testing.

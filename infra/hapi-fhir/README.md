# HAPI FHIR Local Stack

This folder owns the local HAPI FHIR stack for the Medical Chatbot project.

It runs:

- HAPI FHIR JPA Server at `http://localhost:8080/fhir`
- PostgreSQL as HAPI's internal persistence database, published at `localhost:5434`
- Synthetic FHIR resources seeded through the FHIR REST API

The chatbot backend must connect through FHIR REST endpoints. Do not query or modify HAPI PostgreSQL tables directly.

## Run

From the repository root:

```powershell
docker compose -f infra/hapi-fhir/docker-compose.yml up -d
python infra/hapi-fhir/scripts/wait_for_hapi.py
python infra/hapi-fhir/scripts/seed_fhir_data.py
python infra/hapi-fhir/scripts/check_connection.py
```

Run the seed script again any time you want to restore the resources. It posts the JSON transaction Bundle in `seed/`. Each resource uses fixed FHIR IDs and `PUT`, so rerunning the script updates existing resources instead of creating duplicates.

## Synthetic Dataset

The seed is generated by `scripts/generate_fhir_seed.py` into
`seed/synthetic-fhir-transaction-bundle.json`. Regenerate any time with:

```powershell
python infra/hapi-fhir/scripts/generate_fhir_seed.py
```

It produces **100 records of each type** (500 total), cross-linked and clinically
coherent:

| Resource | Count | ID scheme |
|---|---|---|
| Patient | 100 | `BN2026-00001` … `BN2026-00100` |
| Encounter | 100 | `ENC-2026-00001` … |
| Observation | 100 | `OBS-2026-00001` … |
| Condition | 100 | `CON-2026-00001` … |
| MedicationRequest | 100 | `MED-2026-00001` … |

Each patient (`BN2026-000NN`) owns exactly one Encounter, Observation, Condition
and MedicationRequest, all referencing back to the patient. Patients cycle through
10 realistic clinical profiles (`patient_index % 10`):

| Profile | Condition (ICD-10) | Observation (LOINC) | Medication |
|---|---|---|---|
| Hypertension | I10 | Blood pressure panel | Amlodipin 5 mg |
| Type 2 diabetes | E11.9 | HbA1c | Metformin 500 mg |
| Hyperlipidemia | E78.5 | Cholesterol total | Atorvastatin 20 mg |
| Asthma | J45.909 | SpO2 | Salbutamol inhaler |
| Acute URI (resolved) | J06.9 | Body temperature | Paracetamol 500 mg |
| Gastritis | K29.70 | Body weight | Omeprazol 20 mg |
| Hypothyroidism | E03.9 | TSH | Levothyroxin 50 mcg |
| Iron deficiency anemia | D50.9 | Hemoglobin | Ferrous sulfate 325 mg |
| Osteoarthritis | M17.9 | Heart rate | Meloxicam 7.5 mg |
| Migraine | G43.909 | Heart rate | Ibuprofen 400 mg |

Conventions:

- Phone: `09` + zero-padded index, e.g. `BN2026-00001` → `0900000001`.
- Patient identifiers: `http://medical-chatbot.local/patient-id` (= FHIR id) plus an
  MRN `MRN-2026-000NN`.
- Observation values are randomized within realistic ranges; `interpretation`
  (High/Low/Normal) and `referenceRange` are set accordingly.
- Practitioners are referenced by `display` only (HAPI enforces referential
  integrity and no Practitioner resources are seeded).
- `BN2026-00002` and `BN2026-00052` intentionally share the name **Tran Thi Mai**
  to exercise ambiguous-patient selection.

Example Vietnamese chat prompts (the chatbot maps "bệnh nhân N" → `BN2026-000NN`):

```text
Bệnh nhân 1 đang dùng thuốc gì?
Số điện thoại của bệnh nhân 3 là gì?
Cho tôi xem huyết áp gần nhất của bệnh nhân 11
Chẩn đoán của bệnh nhân 2 là gì?
Cholesterol của bệnh nhân 3 là bao nhiêu?
HbA1c của bệnh nhân 12 là bao nhiêu?
```

## Useful Endpoints

- `GET http://localhost:8080/fhir/metadata`
- `GET http://localhost:8080/fhir/Patient?_summary=count`
- `GET http://localhost:8080/fhir/Patient/BN2026-00001`
- `GET http://localhost:8080/fhir/Patient/BN2026-00003`
- `GET http://localhost:8080/fhir/Observation?patient=Patient/BN2026-00001&_sort=-date&_count=5`
- `GET http://localhost:8080/fhir/Observation?patient=Patient/BN2026-00004&_sort=-date&_count=10`
- `GET http://localhost:8080/fhir/Condition?patient=Patient/BN2026-00001`
- `GET http://localhost:8080/fhir/Condition?patient=Patient/BN2026-00004`
- `GET http://localhost:8080/fhir/MedicationRequest?patient=Patient/BN2026-00001`
- `GET http://localhost:8080/fhir/MedicationRequest?patient=Patient/BN2026-00004`

## Backend Connection

When the future backend runs on the host machine:

```env
FHIR_BASE_URL=http://localhost:8080/fhir
```

When it runs inside the same Docker Compose network:

```env
FHIR_BASE_URL=http://hapi-fhir:8080/fhir
```

## Inspect PostgreSQL From Host

The Compose file publishes PostgreSQL to the host:

```text
Host: localhost
Port: 5434
Database: hapi
User: admin
Password: admin
```

For tools that already have a local `postgres` user profile, this dev stack also supports:

```text
Host: localhost
Port: 5434
Database: hapi
User: postgres
Password: postgres
```

Use this only for debugging and learning HAPI's internal schema. Application code should not query HAPI tables directly.

## Stop

```powershell
docker compose -f infra/hapi-fhir/docker-compose.yml down
```

To remove persisted HAPI data too:

```powershell
docker compose -f infra/hapi-fhir/docker-compose.yml down -v
```
